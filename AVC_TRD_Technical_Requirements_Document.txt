2. SYSTEM ARCHITECTURE OVERVIEW
The AVC system is a distributed edge-cloud architecture comprising four logical layers: (1) Wearable Edge (sensor
acquisition + preprocessing), (2) Cloud Signal & Feature Layer (ingestion + feature engineering), (3) Cloud
Inference Layer (deep learning phoneme reconstruction), and (4) Cloud Language & Synthesis Layer (sentence
generation + TTS). All layers communicate over encrypted channels (TLS 1.3 / WPA3).
Layer 1 — Wearable Edge:
PVDF Piezo (32-bit ADC) → MEMS Mic (I2S) → Pressure Sensor (I2C) → Airflow Sensor (I2C) → ESP32-S3 (sync
+ buffer) → WiFi/UDP streaming
Layer 2 — Cloud Signal & Feature:
Ingestion Service → Feature Engineering (13 descriptors: RMS, SPL, Pressure, Velocity, Duration, Energy Ratio,
Duration Norm, SPL/Vel Ratio, Pressure/RMS Ratio, ΔRMS, ΔSPL, ΔPressure, Phoneme-Class)
Layer 3 — Cloud Inference:
Input Projection (D_emb=32) → CNN (64→128→256, 1D conv, BatchNorm+GELU+Dropout) → BiLSTM (3×256
hidden, bidirectional) → 4-Head Self-Attention (residual+LayerNorm) → Classification Head (softmax, label
smoothing)
Layer 4 — Language & Synthesis:
CMU Dict Alignment → Edit-Distance Recovery → GPT-2 LM Re-ranking → FastSpeech2 + HiFi-GAN TTS →
Personalized Voice Stream

4. DATA FLOW & PIPELINE SPECIFICATIONS
4.1 Edge-to-Cloud Streaming Protocol
Protocol: UDP over WiFi (unreliable but low-latency) with application-layer reliability.
Packet Structure: [Header: 8 bytes (seq_no, timestamp_ms, sensor_mask)] [Payload: variable (interleaved sensor
frames)] [Footer: 2 bytes CRC16]
Rate: ~50 KB/sec aggregate (piezo 1kHz×4B + mic 16kHz×2B + pressure 100Hz×4B + airflow 100Hz×4B)
Buffering: 500ms ring buffer on ESP32-S3; retransmission request via BLE if packet loss >2%
Encryption: DTLS 1.3 (datagram TLS) or AES-256-GCM pre-shared key rotation every 24hrs

5.3 Explainability & Monitoring (Offline Path)
SHAP + XGBoost Auxiliary Model: Trained on identical 13-descriptor feature space. SHAP values computed
per-feature using TreeSHAP. Primary use: offline feature importance monitoring, drift detection, and clinical

explainability (why did the model predict /p/ vs /b/?).
Top SHAP-ranked features (research baseline):
1. RMS Amplitude (0.4134) — dominant energy predictor
2. Phoneme-Class (0.2671) — articulation group prior
3. ΔRMS (0.1842) — temporal energy transition
4. Duration (0.1336) — phoneme length
5. SPL (0.1058) — sound pressure level
6. ΔSPL (0.0677) — temporal SPL transition
Note: Pressure, velocity, and ratio-based features showed near-zero SHAP contribution on the small research
dataset. This is a critical monitoring metric — if these features remain uninformative on real patient data, the
sensor stack should be re-evaluated.

6. LANGUAGE & SYNTHESIS LAYER
6.1 Phoneme-to-Word Reconstruction
CMU Dictionary Alignment: Predicted phoneme sequences P = {p■, p■, ..., p■} are matched against the CMU
Pronouncing Dictionary using dynamic programming for optimal segmentation.
Edit-Distance Recovery: Levenshtein distance allows approximate matching when predicted phonemes deviate
from dictionary entries (e.g., substitution of IH0→IH1 under noise).
Candidate Generation: For each phoneme subsequence, retrieve top-k dictionary matches (k=5 default).
Compose candidate word sequences via beam search (beam width=3).
6.2 Language Model Re-Ranking
Model: GPT-2 (or lightweight open-source replacement e.g., LLaMA-3-1B, DistilGPT-2).
Scoring: Score(sentence) = −Loss_LM(sentence). Lower perplexity = higher linguistic plausibility.
Selection: Top-1 candidate from beam search re-ranked by LM score.
TR Decision — GPT-2 Replacement: GPT-2 is non-commercial-friendly and computationally heavy.
Recommendation: Migrate to DistilGPT-2 or a fine-tuned Indic-LM (e.g., AI4Bharat IndicBERT) for Hindi/Telugu
support. This reduces inference cost by ~60% and eliminates OpenAI licensing ambiguity.

7.2 API Specifications
POST /v1/ingest — Stream raw sensor frames from device
Headers: Authorization: Bearer <token>, Content-Type: application/x-avc-stream
Body: Binary protobuf (seq_no, timestamp, sensor_mask, [frames])
Response: 202 Accepted {session_id, estimated_latency_ms}
POST /v1/synthesize — Trigger phoneme reconstruction + TTS
Body: JSON {session_id, user_id, voice_profile_id, language_code}
Response: 200 OK {audio_url, phoneme_sequence, confidence_score, latency_ms}
GET /v1/health — Service health check
Response: 200 OK {status, version, gpu_utilization, queue_depth}
POST /v1/calibrate — Per-user sensor calibration
Body: JSON {user_id, baseline_readings: {pressure, airflow, piezo_rms}}
Response: 200 OK {calibration_vector, confidence}

9. EDGE QUANTIZATION & FUTURE ROADMAP
Current State: Full inference runs in cloud. ESP32-S3 handles only acquisition and streaming.
Phase 2 Edge Plan (2027):
 Quantize CNN-BiLSTM to INT8 using ONNX Runtime + TensorFlow Lite Micro
 Target: partial phoneme classification on edge (top-3 candidates); full refinement in cloud
 Reduces cloud dependency for common phrases; enables offline mode
 Memory budget: ≤2MB model size for ESP32-S3 PSRAM
Phase 3 Edge Plan (2028):
 Evaluate ESP32-P4 or ARM Cortex-M55 + Ethos-U55 NPU for full edge inference
 Target: <100ms edge-only latency for 50 common phrases
 Cloud reserved for personalization, model updates, and analytics
10. TESTING & VALIDATION STRATEGY
Unit Testing: pytest for feature engineering, model forward pass, API endpoints
Integration Testing: End-to-end pipeline with synthetic sensor data (phantom speech simulator)
Model Validation: Stratified k-fold cross-validation (k=5); held-out patient cohorts; confusion matrix per
phoneme class
Latency Testing: p50, p95, p99 latency benchmarks under load (Locust/k6)
Security Testing: OWASP ZAP penetration testing; fuzzing of ingestion API
Clinical Validation: 10-patient pilot at AIIMS; IRB-approved protocol; primary endpoint: intelligibility score
(CIID)
