# AVC ESP32-S3 Firmware

Sensor acquisition + UDP transport for the AVC (Artificial Vocal Card)
pipeline. One board reads the four TRD sensors, buffers 500 ms windows,
serializes them into the pinned wire format, and ships one UDP datagram
per window to the gateway host.

```
mic (I2S, 16 kHz) ─┐
piezo (ADC, 1 kHz) ─┤  500 ms window → packet.c → CRC16 → UDP datagram
pressure (100 Hz) ─┤                    │
airflow (100 Hz) ──┘                    └→ scripts/udp_capture.py (Python)
                                          → services.ingest.parse_packet
                                          → services.pipeline (Layers 2–4)
```

## Layout

| File | Purpose |
|---|---|
| `main/packet.h` / `main/packet.c` | Wire-format serializer — **byte-for-byte mirror of `services/ingest.py`** |
| `main/main.c` | Acquisition task (paced off the 16 kHz mic clock) + WiFi/UDP |
| `main/Kconfig.projbuild` | WiFi credentials, gateway IP/port, synthetic-data switch |
| `test/test_packet.c` | Host-runnable lockstep test — golden vectors + argument validation |

## Wire format (pinned — do not change one side without the other)

```
Header (9 bytes, LE):   uint32 seq_no | uint32 timestamp_ms | uint8 sensor_mask
                        (bit0=mic, bit1=piezo, bit2=pressure, bit3=airflow)
Payload: per enabled sensor, ascending bit order:
                        uint16 sample_count | int16 samples[count] (LE)
Footer:                 uint16 CRC16-CCITT (poly 0x1021, init 0xFFFF,
                        no reflect, no final xor) over header+payload
```

Max packet ≈ 17 KB (all four sensors at full 500 ms budgets:
8000 + 500 + 50 + 50 samples) — fits comfortably in one UDP datagram on
the local network.

## Status: skeleton (Milestone 1)

Working now:

- Packet serialization + CRC, lockstep-tested against the Python side.
- Window pacing (mic-clocked; piezo ÷16, pressure/airflow ÷160).
- WiFi STA + UDP transmit + auto-reconnect.
- **Synthetic sensor mode** (default): deterministic test signals on all
  four channels so the full firmware→UDP→Python path can be validated with
  only a board — no sensors needed.

Not yet (blocked on hardware answers — see repo README "Open questions"):

- Real I2S mic driver, ADC piezo/pressure/airflow drivers, pinout.
- Battery/power path, enclosures, board bring-up validation.

## Building

Requires ESP-IDF v5.x:

```bash
cd firmware
idf.py set-target esp32s3
idf.py menuconfig    # AVC Configuration: SSID, password, gateway IP/port
idf.py build
idf.py -p COMx flash monitor
```

The default build enables synthetic sensors
(`AVC_SYNTHETIC_SENSORS=y`). Disable it in menuconfig once real drivers
are wired in.

## Host lockstep test (no ESP-IDF needed)

`test/test_packet.c` runs on any C99 host compiler and replays golden
vectors generated by the Python side:

```bash
cd firmware/test
gcc -std=c99 -Wall -Wextra -I../main -o test_packet test_packet.c ../main/packet.c
./test_packet
```

(The AVC repo's main CI does the equivalent; there is no C compiler on
the original dev machine, so this is expected to run elsewhere.)

### Regenerating golden vectors

Vectors live as hex literals in `test/test_packet.c`. If either side of
the wire format changes, regenerate **both sides together** from the repo
root:

```python
from services.ingest import build_packet
print(build_packet(287454020, 48879, {"mic": [0.5, -0.25, 0.0],
    "piezo": [0.1, -0.1], "pressure": [0.5], "airflow": [-0.2]}).hex())
```

Then update the embedded hex + sample lists in `test_packet.c` and the
mirrored expectations in `tests/test_ingest.py`.
